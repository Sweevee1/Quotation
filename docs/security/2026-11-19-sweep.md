# Security sweep (2026-11-19)

Run because cbffa69 added an unauthenticated public quotes page (a second listener on `PUBLIC_PORT`) and an API-key
integration API for SweevElements. Modelled on SweevElements' 2026-10-08 pre-launch sweep. All testing was against a
local dev server only; no live host was probed.

> **Breaking change for existing installs (Unraid included):** with `NODE_ENV=production` the server now refuses to
> start unless `SESSION_SECRET` is at least 32 characters and not a known default, and `WEBUI_PASSWORD` is not
> `change-me`. `.env.example` now leaves both blank. Set them before pulling the new image. Also check `TRUST_PROXY`
> (default `1`): set `0` if the container is reached directly, with no reverse proxy in front.

## Method
| Layer | Tool | Result |
|---|---|---|
| Dependencies | `npm audit` (prod and full tree) | prod initially: `proxy-addr` critical, `body-parser` high, `zod` high, `qs` moderate |
| Manual / AI | 3 independent read-only code reviews (public page + API, admin auth, container + CI) | findings checked against the code, see below |
| Black-box | `curl` against a local dev server | XSS payload quotes, public-port isolation, headers, redirect, bad ids, rate limit (incl. `X-Forwarded-For` spoofing), login flood, API key, oversized body |

**Not run:** gitleaks, Semgrep, Trivy, OSV-Scanner (Docker Desktop was not running), `docker build`, GitHub workflows,
live host probes. Run the scanners before launch.

## Findings
Confirmed on the dev server before the fixes went in:
- Reflected XSS in `/twitch/callback?error=` (no escaping, no CSP).
- No login rate limit (30 wrong passwords, all 401).
- Rate limit bypassed by spoofing `X-Forwarded-For` on the public port (100 spoofed requests, all 200).
- Oversized JSON body returned 500.

Confirmed in code only:
- `SESSION_SECRET` defaulted to `dev-only-insecure-secret` with no production guard, so the admin cookie could be forged.
- Sync bcrypt blocked the event loop; sessions survived a password change; backup restore was not transactional;
  the OAuth `code` appeared in request logs; a chat-template reply could start with a command prefix (`/`, `.`);
  LIKE wildcards in search were not escaped; the public app had no error handler; 404s sent `Cache-Control: public`.
- Container ran as root, no `.dockerignore`, unpinned actions, compose ports on 0.0.0.0, no security CI or Dependabot,
  `npm ci` ran install scripts, no healthcheck.

## Fixed in this sweep
- **Auth / XSS:** popup message escaped, nonce CSP, `postMessage` to own origin, dashboard listener same-origin only
  (e21656c). Login and change-password share a limit of 10 attempts per 15 min per IP; bcrypt is async (614d464).
  Sessions carry a password-hash fingerprint, so a password change invalidates other cookies; cookie lifetime is
  now 7 days instead of 30 (fe3e253). OAuth callback query string no longer logged (30a5844).
- **Production guard:** refuses to start with default or short secrets, or the default password (3777a68).
- **Trust proxy:** configurable through `TRUST_PROXY` (default 1, set 0 if directly exposed); the public rate limit now
  applies only to the quotes paths (0a85eb9).
- **Public page:** literal LIKE search, page cap 1000, `no-store` on non-200 and 429 responses, public error handler
  (17db55f; escaping regex corrected in 3bd4335).
- **Errors / data:** body-parser 4xx (413, 400) passed through instead of 500 (b61d4be). Restore runs in one
  transaction, duplicate import ids are rejected, restore failures return 500 instead of 404 (fae7baf). Chat replies
  starting with `/` or `.` get a `> ` prefix (157076b).
- **Dependencies:** express 4.22.3, body-parser 1.20.9, qs 6.16.2, proxy-addr 2.0.8 (462ec76); zod 4.6.7 (c661c47).
- **Container:** `.dockerignore` (e2e82b1). Runs as non-root: a gosu entrypoint chowns `/app/data` to 99:100, then
  drops privileges. Healthcheck on `/api/auth/me`; `npm ci --ignore-scripts` (65f6921). Compose ports bound to
  127.0.0.1 (c188592, 9a4a675).
- **CI:** SHA-pinned actions, an audit job that gates the image push, a SHA image tag, least-privilege permissions
  (397d99f). `security.yml` runs npm audit and OSV on push, on PRs and daily; `dependabot.yml` covers npm, actions and
  docker (1e46da2).
- **Repo / docs:** `.gitignore` covers env variants, keys and db files; `.env.example` leaves the required secrets
  blank (2a602cd). README has deployment security notes (8a038a3).

## Verified after the fixes (dev server)
- The XSS payload comes back escaped, under a nonce CSP. The public page still escapes payload quotes.
- 30 wrong logins: 7x 401, then 23x 429.
- With `TRUST_PROXY=0`, spoofed `X-Forwarded-For` no longer gets past the 90/min limit (95 requests: 87x 200, 8x 429).
- `q=%25` matches only a literal `%`. A 200 KB body returns 413.
- A cookie issued before a password change is rejected afterwards.
- `NODE_ENV=production` with a short `SESSION_SECRET` exits 1.
- `npm audit --omit=dev --audit-level=high` exits 0 after the zod 4 upgrade; zod 4 validation probes return 400, not 500.

## Accepted / not code
- Twitch client secret and bot tokens are stored in plaintext in the SQLite `settings` table. This relies on `data/`
  permissions; consider encryption at rest later.
- Sessions are otherwise stateless (`cookie-session`). `sameSite=lax` is the CSRF defence. The cookie is not `Secure`
  on plain-HTTP LAN installs, by design.
- **The main `PORT` also serves the public router and the admin login.** Never forward it to the internet; forward
  only `PUBLIC_PORT`.
- The bundled self-signed TLS listener needs a browser click-through.
- Remaining moderate esbuild advisories are dev-only, via drizzle-kit (fixing them needs `npm audit fix --force`).
- The README recommends a public GHCR package and `:latest` (a SHA tag is now available for pinning).
